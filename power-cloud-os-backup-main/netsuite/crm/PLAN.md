## Conventions used by every task

- **Deal UUID** `D` is the opportunity's `custbody_pc_deal_uuid` (set at intake by the API; for migrated deals set by T6). **Namespaced external ids**: opportunity `pc_opp_{D}`, project `pc_proj_{D}`, project task `pc_task_{D}_{n}` (n = 1..3, or `default`), ledger row `pc_req_{requestId}`. NetSuite enforces external id uniqueness per record family, so a second save with the same external id fails: that failure is the atomic claim.
- **Operation ledger** `customrecord_pc_op_ledger` (T1) holds one row per mutation request: action, request id (name and external id), payload hash, opportunity, project, step reached, status (pending, done, failed, refused), result JSON, requester role, timestamps. Replay with the same request id and hash returns the stored result; same id with a different hash is refused; a failed row resumes from its step.
- **Test isolation**: any opportunity whose title starts with `ZZ TEST` is a test record. The builder sets `custentity_pc_travel_exclude` on the project in its first save, skips the relay refresh, and honors the fault-injection parameter `custscript_pc_fail_after_step` (script parameter on the suitelet and RESTlet) only for test records.
- **Status machine** (opportunity `entitystatus`): open statuses 6, 7, 8, 9, 10, 11, 12, 18, 19, 21 move among themselves only; 24 (Won - Awaiting Project) is entered only by `closeOpportunity` won from an open status; 24 → 25 only by the builder; 25 → 23 by `updateOpportunity` with a kickoff date; 13 (Closed Won) is set by the builder after 23 or directly by `closeOpportunity` for engagement types with no project (Power Cloud Product, New License Deal); 14 (Closed Lost) only by `closeOpportunity` lost from an open status; nothing moves out of 13 or 14.

## T2. Builder module, suitelet, opportunity user event, client script (SDF; deployments in Testing until T7)

Files under `src/FileCabinet/SuiteScripts/PC/` (built as `pc_crm_*.js`; script ids are `customscript_pc_crm_*`, see `docs/FDD_TDD_tables.md`; the names below are the v2 draft names):

- `pc_readiness.js`: `check(opp)` → `{ok, missing[], noProject, state}` where `state` is one of `fresh` (no links, no ledger row), `partial` (a project with external id `pc_proj_{D}` exists, or a ledger row is pending or failed), `complete` (both links set and the ledger row is done), `conflict` (links point at different projects, or the linked project is inactive). Readiness for **creation** requires `state = fresh` plus: End Client; class with a single active channel row; `custbody_pc_billing_party` equal to the resolved billing party; Partner when relationship = Referral; engagement type with a mapping; commercial model; `custbody_opp_rate` > 0; `custbody_opp_principal`; `custbody_pc_signed_date`; `entitystatus` = 24. Readiness for **resume** requires `state = partial` and the same field checks. `conflict` and `complete` are refused with a message.
- `pc_project_builder.js`: `build(oppId, requestId, options)`. (0) Claim the ledger row (`pc_req_{requestId}`; an existing done row returns its result; an existing failed row resumes; a hash mismatch refuses). (1) Determine `state`; refuse unless fresh or partial. (2) Look up the project by external id `pc_proj_{D}`; if absent, create it in one save with: `externalid` = `pc_proj_{D}`, `companyname` = title, `parent` = billing party (Subcontract) or entity (Referral, Direct), `entitystatus` 5, `jobtype` from `pc_types`, `custentity_pc_end_client` ← `custbody_pc_referral_end_user`, `custentity_cus_rev_src` ← `class`, `custentity_pc_commercial_model` ← `custbody_pc_commercial_model`, `custentity_pc_partner_contact` ← `custbody_pc_partner_contact`, `custentity_pc_deal_uuid` ← `custbody_pc_deal_uuid`, `custentity_pc_asana_url` ← `custbody_opp_asana_proj`, `custentity_pc_project_billable_rate` ← `custbody_opp_rate`, `custentity_job_billings` ← `projectedtotal`, `custentity_pc_proj_principal` ← `custbody_opp_principal`, `custentity_pc_sen_consultant` ← `custbody_opp_proj_srcon`, `custentity_pc_proj_staff_cons` ← `custbody_opp_proj_staff`, `custentity_proj_lead_dev` ← `custbody_opp_proj_leaddev`, `startdate` ← `custbody_opp_kickoff_meet` when set, `allowtime` T, `allowexpenses` T, `allowallresourcesfortasks` T, `projectexpensetype` -2, `custentity_pc_travel_exclude` T when the title starts with `ZZ TEST`. (3) Set `custbody_opp_proj_create` on the opportunity; then try native `job`: NetSuite only accepts a project that belongs to the opportunity's entity, so on Subcontract deals (parent ≠ entity) the set is expected to fail; catch it, record `nativeLink: false` in the ledger result, keep going.
